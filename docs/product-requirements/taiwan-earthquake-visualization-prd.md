# 台灣地震熱區探索器 MVP PRD

## 1. 文件目的

本文件整理「台灣地震熱區探索器」MVP 的產品需求，作為後續設計、開發與驗收依據。

本階段目標是把現有地震資料做成一個本機可使用的互動式視覺化專案。重點是完成可操作、可展示、可重跑資料處理流程的 MVP，而不是建立完整研究平台或公開服務。

## 2. 專案背景

使用者過去曾規劃地震資料專案，但尚未完成可展示成果。這次希望透過「台灣地震熱區探索器」走完從需求收斂、資料整理、前端視覺化到本機可運行的完整流程，並練習使用 Codex CLI 輔助開發。

此專案延續既有提案方向：以台灣地震資料為主，製作互動式地圖，呈現歷年地震熱區、點位、發生頻率與震級篩選。

## 3. 目標使用者

主要使用者是專案作者本人。

本 MVP 優先滿足作者在本機探索台灣地震資料、檢視熱區分布、篩選年份與震級的需求。外部評審、一般民眾、研究人員或作品集面試官不是本階段的主要受眾。

## 4. 產品目標

完成一個本機可啟動的台灣地震互動視覺化網頁，使用現成 CSV 資料，透過地圖呈現台灣地震熱區與地震點位，並支援年份與震級篩選。

MVP 必須做到：

- 能讀入並整理現有地震 CSV 資料。
- 能產出乾淨的合併資料檔供前端使用。
- 能保留可重跑的資料清理流程。
- 能在台灣地圖上清楚呈現地震熱區。
- 能顯示地震點位。
- 能依年份篩選。
- 能依震級篩選。
- 能在本機穩定啟動與操作。

## 5. 非目標

以下項目明確不列入本次 MVP：

- 地震預測模型。
- 3D 深度場景。
- 亞洲或全球地震資料。
- 即時自動更新。
- 手機版精緻適配。
- 公開網址部署。
- 作品集級高精緻視覺包裝。

## 6. 核心體驗

使用者打開本機網頁後，第一眼看到的是台灣地震熱區地圖。

地圖主要回答的問題是：台灣哪些地區在歷史資料中地震發生較頻繁？

初版熱區計算以地震次數為主，不以震級或能量加權作為必要條件。未來若有時間，可再加入震級權重，讓熱區同時反映發生頻率與強度。

同一個主畫面需要支援地震點位顯示、年份篩選與震級篩選。點擊地震點或熱區顯示摘要資訊是理想需求；若時間不足，點擊詳情可以降級或延後。

## 7. 功能需求

### 7.1 地震熱區地圖

系統應在台灣地圖上呈現歷年地震熱區。

需求：

- 熱區以地震發生次數為基礎。
- 地圖範圍以台灣及周邊地震資料為主。
- 熱區視覺化需能清楚看出高頻區域。
- 熱區需隨年份與震級篩選結果更新。

### 7.2 地震點位

系統應在地圖上顯示地震事件點位。

需求：

- 點位需對應資料中的經緯度。
- 點位可使用震級或其他方式做基本視覺區分。
- 點位需隨年份與震級篩選結果更新。
- 點擊點位顯示摘要資訊列為本次理想功能；若時程不足，可先保留地圖點位顯示而不做完整詳情。

### 7.3 年份篩選

系統應提供年份篩選。

需求：

- 使用者可以選擇資料年份或年份範圍。
- 熱區與點位需依年份篩選結果更新。
- 年份篩選必須可用，屬於 MVP 完成條件。

### 7.4 震級篩選

系統應提供震級篩選。

需求：

- 使用者可以依震級門檻或範圍篩選地震事件。
- 熱區與點位需依震級篩選結果更新。
- 震級篩選必須可用，屬於 MVP 完成條件。

### 7.5 地圖互動

系統應支援基本地圖互動。

需求：

- 可拖拉地圖。
- 可縮放地圖。
- 地圖操作需在本機環境中穩定。

### 7.6 點擊摘要資訊

系統理想上應支援點擊地震點或熱區後顯示摘要資訊。

需求：

- 點擊單筆地震時，可顯示基本欄位，例如時間、位置、震級、深度。
- 若支援熱區點擊，可顯示該區事件數量或篩選後摘要。
- 此功能重要性低於熱區、點位、年份篩選與震級篩選；時間不足時可先降級。

## 8. 資料需求

### 8.1 資料來源

本 MVP 使用現有資料夾作為資料來源：

`(彭元懋)_台灣地震活動彙整`

目前已確認資料夾內有 1995 至 2024 年的年度 CSV，並有一個 2025 子資料夾。

### 8.2 資料範圍

需求：

- 1995 至 2024 年 CSV 必須納入處理。
- 2025 資料需先檢查格式。
- 若 2025 資料格式可自動合併，則納入 MVP。
- 若 2025 資料格式不一致或需要額外人工處理，則本次可暫不納入，並在文件或介面中清楚標註。

### 8.3 資料處理

資料處理需做到：

- 讀取原始 CSV。
- 清理欄位與資料型別。
- 合併年度資料。
- 輸出乾淨的前端可讀資料檔。
- 保留可重跑的清理腳本。

資料處理不要求做到即時自動更新，也不要求建立完整資料庫。

## 9. 技術方向

本階段採用提案中的技術方向：

- 使用 Python 進行資料清理與合併。
- 使用 React 建立前端互動介面。
- 使用 deck.gl 作為主要地圖視覺化工具。
- 本機可啟動即可，不要求公開部署。

技術選型的重點是支撐 MVP 需求，不追求過度工程化。

## 10. 使用情境

### 情境 1：查看台灣地震熱區

使用者啟動本機網頁後，看到台灣地圖上的地震熱區，能快速理解哪些區域在歷史資料中地震發生較頻繁。

### 情境 2：依年份觀察變化

使用者調整年份篩選後，熱區與點位同步更新，用來觀察不同年份或時間範圍內的地震分布差異。

### 情境 3：依震級聚焦較大地震

使用者調整震級篩選後，只查看符合震級條件的地震事件，並觀察熱區是否集中於特定地區。

### 情境 4：檢視單筆地震摘要

若點擊摘要功能完成，使用者可點擊地震點查看事件基本資訊，例如時間、震級、深度與位置。

## 11. 優先級

### P0：必做

- 讀取與整理 1995 至 2024 年資料。
- 檢查 2025 資料是否可納入。
- 產出乾淨合併資料檔。
- 保留可重跑資料清理腳本。
- 台灣地震熱區地圖。
- 地震點位顯示。
- 年份篩選。
- 震級篩選。
- 地圖拖拉與縮放。
- 本機可啟動使用。

### P1：盡量做

- 點擊地震點顯示摘要資訊。
- 點擊熱區顯示摘要資訊。
- 基本圖例與篩選狀態提示。
- 介面整理到不粗糙、可展示給自己檢查成果的程度。

### P2：本次不做

- 震級權重熱區。
- 3D 場景。
- 即時資料更新。
- 公開部署。
- 手機版精緻適配。
- 跨國或全球地震資料。

## 12. 驗收標準

MVP 完成時需符合以下條件：

- 在本機可啟動專案並打開互動網頁。
- 網頁顯示台灣地震熱區。
- 網頁顯示地震點位。
- 年份篩選能正常改變熱區與點位結果。
- 震級篩選能正常改變熱區與點位結果。
- 1995 至 2024 年資料能被正確讀入與合併。
- 2025 資料若格式可處理，能被納入；若不能納入，需明確標註原因。
- 資料清理流程可以重跑並重新產生前端資料檔。
- UI 不需要高度精緻，但不能像臨時測試頁；需達到清楚、可用、不粗糙。

## 13. 風險與注意事項

- 原始 CSV 欄位格式可能跨年份不一致，需要先檢查欄位名稱、日期格式、經緯度、震級與深度欄位。
- 2025 資料位於子資料夾，格式可能與 1995 至 2024 年 CSV 不同。
- deck.gl 地圖效能需注意資料量，必要時可先做資料聚合或簡化。
- 熱區與點位同時顯示時，視覺可能互相干擾，需要透過透明度、圖層切換或樣式調整確保可讀性。
- 點擊熱區摘要可能比點擊單筆點位複雜，若時程不足應先確保 P0 功能完成。

## 14. 後續可延伸方向

MVP 完成後，可考慮以下延伸：

- 熱區加入震級或地震能量權重。
- 加入深度視覺化。
- 加入時間演化動畫。
- 補上更完整的 README 與操作說明。
- 部署成公開網址。
- 強化手機版體驗。
- 加入 3D 視覺化或 three.js 場景。
